# Issues #332, #350, #383, #394, and #397 Batch Design

## Goal

Complete the five open desktop issues in one origin/main-based branch and one
final pull request, while keeping Rust authoritative for product state and
preserving the existing timeline, composer, and Tauri transport contracts.

## Scope and decisions

### #397 — Room/DM search scope

The product exposes one current-conversation scope labelled `Room/DM`. It
resolves to the selected room ID for both ordinary rooms and DMs. The separate
all-DMs scope is removed from the user-facing selector and the Rust/TypeScript
scope contract. `Space` remains a separate scope and `All` remains available as
an explicit, opt-in global search.

The default is `Room/DM`. A missing active conversation is an unavailable
scoped search, never a reason to fall back to `AllRooms`. The browser fake,
Tauri resolver, core command, SDK search scope, i18n labels, and focused tests
share the same contract.

### #383 — macOS full-bleed icon

The existing transparent, pre-rounded photon SVG remains the cross-platform
source. A new macOS-only SVG is opaque at every corner and uses the same photon
artwork inside a safe area without a baked outer mask. The icon generation
script selects this source only for the macOS ICNS inputs; Windows, Linux, web,
and in-app assets continue to use the existing source.

Generation stays reproducible on non-macOS hosts through the checked-in ICNS
helper. A script-level test verifies the macOS source has an opaque full-bleed
background and that the generated ICNS is built from the macOS raster inputs.

### #350 — scheduled-message body editing

The formatting toolbar and IME-safe editor mechanics are extracted from the
normal Composer into a reusable editor surface. The scheduled-message form
uses that surface with the shared bold, italic, link, list, code, emoji, and
mention affordances plus the existing date-time control; it does not create a
second toolbar implementation.

The core update operation carries `scheduled_id`, `body`, and `send_at_ms`.
Local fallback items are updated in `ScheduledSendStore`. Server delayed
events are cancelled and recreated with the new body/time through the existing
fallback path, and the resulting item is projected only after the operation's
authoritative completion. Existing cancel and send-at-time behavior remains
unchanged.

### #332 — Home and Space thread aggregation

The existing room-scoped Threads entry remains supported. Thread list state and
items gain an explicit Rust-owned scope and room ownership for each row:

- `Room(room_id)` for the current room header entry;
- `Home` for all joined conversation rooms;
- `Space(space_id)` for the selected space's child rooms.

The core thread-list actor opens one SDK `ThreadListService` per room in the
requested scope, merges rows by `(room_id, root_event_id)`, applies the
Rust-owned thread-list ordering, and emits one aggregate snapshot. A page
request advances each participating service by one bounded SDK page. Room
membership and space-child membership are resolved before the subscription is
created; an unreliable space membership set produces an empty/unavailable
space view rather than global data. Every aggregate row carries `room_id`, so
opening a row selects its owning room before opening the thread.

The Home and Space entry points use the existing right-panel system and do not
derive rows in React from room timelines, unread counts, or visible thread
chips.

### #394 — pinned-message panel and event-ID navigation

The existing pin projection remains sourced from `m.room.pinned_events`, but
the passive timeline block becomes a compact clickable entry point. A new
room-scoped `pinned` right-panel mode renders the ordered pinned IDs and their
Rust-owned preview/state data.

Selecting a row uses the event ID as the only target identity. Core first uses
the existing event-cache `load_or_fetch_event` and targeted timeline repair,
then opens the existing Focused/anchored timeline projection. The pinned panel
stays open while the center timeline navigates and briefly marks the target.
The latest-message anchor is never used as a fallback. Root events navigate in
the main timeline; thread replies carry their thread-root relation and open
the owning thread before focusing the reply. Failed load/repair leaves the
panel open with a retryable error state.

## Data flow

1. React dispatches typed intent through the existing Tauri command layer.
2. The reducer validates session, active scope, and request identity before
   emitting an effect.
3. Core actors perform SDK/event-cache work, then emit typed actions and
   `CoreEvent` mirrors.
4. Rust projects the resulting state through the existing DTO and state-delta
   paths. React renders the DTO and never repairs scope, ordering, pin
   membership, or thread aggregation locally.

## Verification

- Rust reducer/core tests cover search no-fallback behavior, scheduled update
  semantics, aggregate scope membership/deduplication/order, and pinned target
  navigation/error transitions.
- TypeScript/Vitest tests cover selector/default behavior, shared scheduled
  editor controls, right-panel mode/row actions, and Home/Space row ownership.
- The icon generator has a deterministic source/corner-opacity contract test.
- The existing IME inventory and contract gates run after the scheduled editor
  change.
- Focused headless local QA covers scheduled update, pinned navigation, and
  aggregated thread scopes; the final gate includes typecheck, Rust tests,
  desktop tests/lint, SDK-path guard, and `git diff --check`.

## Non-goals

- Changing Matrix pinning, delayed-event, or thread protocols.
- Replacing the existing timeline virtualization or gap-repair architecture.
- Adding a global pinned-message index.
- Reworking unrelated composer send/edit behavior beyond extracting shared
  editor primitives.
