# Issues #414–#416 Design

## Scope

Implement the three 2026-08-03 desktop UI issues as one release change:

- #414: Element/Compound-compatible generated Space avatars.
- #415: one structured inline mention editor shared by compose, thread, and edit surfaces.
- #416: compact Space-members navigation in the Space header action row.

Unrelated room/user avatar behavior, Matrix state semantics, member loading, and composer lifecycle fencing remain unchanged.

## #414 Space fallback avatars

Add pure frontend helpers for Compound’s pinned behavior:

- `elementAvatarInitial(name)` removes one leading `@`, `#`, or `+`, then returns the first `Intl.Segmenter` grapheme. CSS performs uppercase presentation.
- `elementAvatarColorIndex(id)` sums UTF-16 code units and returns `(sum % 6) + 1`.

`WorkspaceRail` keeps source precedence: usable Matrix image, explicit local icon override, then generated initial from the effective displayed Space name (including a local display-name override and the existing room-ID/`?` nonblank fallback). The generated path is explicitly Space-only so `EntityAvatar`’s existing room/user behavior does not change. Six semantic CSS background/text pairs mirror Compound design tokens 10.1.0 for light and dark themes. Both image and fallback Space tiles use a 25% radius, 1:1 geometry, and the existing failed-image fallback. Generated initials do not use compact-label wrapping or shrinking. A visible fallback border remains available in forced/high-contrast mode.

## #415 Structured mention document

### Authoritative model

Use a versioned document at the state/IPC boundary:

```ts
type ComposerInline =
  | { kind: "text"; text: string }
  | { kind: "mention"; target: MentionTarget; display_label: string };

type ComposerDocument = {
  version: 2;
  inlines: ComposerInline[];
};
```

Equivalent serde types live in `koushi-state`. Adjacent text nodes are normalized, empty text nodes are discarded, mention occurrences remain distinct, and Matrix IDs are deduplicated only while deriving `MentionIntent`. Plain body, formatted body, and mention metadata are derived from one immutable document snapshot. Manually typed or pasted matching text remains a text node.

### Persistence and transport

`ComposerDraftStore` stores `ComposerDocument` values for room and thread drafts while preserving its existing revision, lease, debounce, account scope, and accepted-clear fences. Persistence advances to schema V3. V1/V2 string entries decode losslessly into one text node and never infer mentions. Snapshot/Delta/Tauri/TypeScript/browser-fake fixtures carry the document together with the derived plain draft required by existing display and diagnostics contracts.

Draft update commands submit the structured document. Rust normalizes it and derives the plain draft; callers cannot independently submit mismatching visible text and mention metadata. Send/reply/thread/edit commands likewise consume a document, with Core deriving the final Matrix content.

### Shared editor

Add an IME-owned rich text control beside the existing textarea primitive in `ImeTextControl.tsx`; raw `contentEditable` remains confined to this approved primitive. The control renders text nodes and `contentEditable=false` mention spans in one editing host. A shared controller maps DOM selection to document boundaries and handles insertion, Backspace, Delete, intersecting range deletion, cut, undo, redo, arrow boundaries, clipboard plain text, autocomplete query replacement, and composition ownership.

Native editing is allowed only for text that does not intersect mention nodes. Entity-changing edits create one document-history transaction so visual content and metadata undo/redo together. Copy exports readable `@Display Name`; ordinary paste inserts text only. Mention spans have an accessible mention label.

`Composer` uses this control for main and thread surfaces. `TimelineView` reuses `Composer` around the same control for text and media-caption edits; a second editor wrapper would duplicate that controller, so none is added. Only surrounding chrome remains surface-specific. Enter/Shift+Enter, Escape, macOS editing keys, scheduling, reply state, attachment staging, multiline editing, CJK/emoji text, and draft generation fencing retain their current contracts. The separate mention-pill row and `pruneMentionIntentForDraft` heuristic are removed.

### Matrix serialization

Rust serializes text nodes through the existing markdown policy and mention nodes as escaped readable plain labels plus safe `matrix.to` anchors in formatted HTML. Top-level normal-send `m.mentions` is derived from all final entities and deduplicated by Matrix ID; `room: true` comes only from a room-mention entity.

For edits, the replacement relation carries the complete final mention set. The top-level edit notification set is the final set minus the Rust-projected original set, preserving #382 semantics. Existing timeline projection supplies the initial editable structured document from sanitized formatted mention links plus typed event mention metadata; identity is never reconstructed from a display-label substring in React.
