# Issue #755 Phase C

Status: implemented and locally verified; different-model integration checkpoint pending.

## Scope

Core media-save security policy over a narrow filesystem port only. Phases D/E
remain untouched.

## Implementation

- Added `koushi_core::media_save` with `MediaSaveFilesystem`, closed
  `MediaSaveIoError`/`MediaSaveError`, safe filename/default path helpers, and
  canonical source containment plus ordered parent creation/copy admission.
- Moved the native `std::fs` implementation to the Tauri adapter. Tauri now
  resolves the app-data media cache root and selected/download roots, then
  delegates save policy to Core.
- Added synthetic fake-port coverage for validation, missing/outside/sibling/
  symlink paths, parent/copy failures, operation ordering, success, filename
  sanitization, private-safe errors, and a real Unix temporary symlink check.
- Updated portability, state-machine, frontend ownership inventory, and
  operational ownership notes. No AppState/AppAction/reducer transition was
  added.

## Verification

- RED: `cargo test -p koushi-core --test media_save --no-run` failed because
  the new Core API was absent.
- GREEN: `cargo test -p koushi-core --test media_save` — 9 passed.
- `cargo test -p koushi-core --lib` — 936 passed, 8 ignored.
- `cargo test --manifest-path apps/desktop/src-tauri/Cargo.toml` — 109 library
  tests and 5 integration tests passed.
- `cargo fmt --all -- --check`, strict Rust test-structure checker,
  `node --test scripts/check-rust-test-structure.test.mjs`,
  `node scripts/check-agents-docs.mjs`, and `git diff --check` — passed.

The adapter retains only app-data/download-root resolution, the selected
filesystem paths, and native `std::fs` port calls. No media-save validation,
canonicalization, parent-creation ordering, copy admission, or path-bearing
error policy remains there. Transport strings retain the prior whitespace
normalization before conversion to paths.
