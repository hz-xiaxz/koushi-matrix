# Issue #759 Phase A1 checkpoint — Core state event cutover

Status: implemented, locally verified and Fireworks `reviewer-flash` approved `CORRECT-TO-CONTINUE`.

## Scope

- Removed legacy `CoreEvent::StateChanged` and both runtime full-state broadcasts.
- Kept latest-wins `VersionedAppStateSnapshot` watch publication, including
  same-generation Core-only refreshes.
- Promoted `CoreConnection::next_versioned_snapshot` as the causal watch barrier.
- Migrated Core, Tauri tests, headless QA and real-homeserver QA consumers to
  snapshot-watch predicates, `StateDelta` wakes or existing typed events.
- Updated the strict QA structure marker from the removed full event to
  `StateDelta`.

The Tauri/React versioned desktop envelope and removal of the second state-wake
URI are Phase A2 and are intentionally not claimed here.

## Verify-first evidence

The approved design/canon base is `9f7e9f1`; its production base is
`origin/main` `2591e106`. The two new `runtime_core` checks were copied unchanged
onto a disposable `2591e106` worktree before accepting the production deletion:

- `reducer_actions_coalesce_into_one_contiguous_delta_without_full_snapshot_events`
  failed because one non-delta full-state event was observed.
- `snapshot_only_refresh_wakes_watch_without_advancing_generation_or_emitting_delta`
  failed because the snapshot-only refresh also broadcast an event.

The disposable baseline worktree was removed after recording both failures; the
issue worktree's dependency cache was retained and only its `koushi-core` package
artifact was rebuilt after baseline metadata contamination was detected.
