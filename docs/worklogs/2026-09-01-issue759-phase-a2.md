# Issue #759 Phase A2 checkpoint — v1 desktop state-update lane

Status: implemented, locally verified and Fireworks `reviewer-flash` approved `CORRECT-TO-CONTINUE`.

## Scope

- Added the adapter-owned v1 `delta` / `snapshot` state-update envelope and
  `koushi-desktop://state-update` event lane.
- Removed normal `StateDelta` duplication from the generic Core-event lane and
  removed the session-specific full-refresh wake.
- Lag recovery now emits an exact generation-bearing full snapshot, emits the
  typed timeline `ResyncMarker`, and submits one `ReplaySubscribed` command.
- Added `resync_snapshot` for frontend-detected gaps; it captures one exact
  versioned snapshot and requests one timeline replay.
- Replaced `listenStateChanges` with typed `listenStateUpdates`.
- Installed the Tauri state listener before the initial snapshot read, queues
  updates during initialization, applies contiguous deltas, ignores stale
  updates, and performs one snapshot+timeline resync on a generation gap or
  rejected contiguous delta.
- Removed the legacy state wake timer/listener and generic CoreEvent StateDelta
  consumer. Browser fake, IPC mock and Playwright harness mirror the v1 shape.
- Resync failure starts no timer/backoff and retains its queued trigger; only a
  later external update retries. If initial read and resync both fail and no
  further update arrives, the renderer remains fail-closed without a snapshot.

Phase B command-return snapshot removal is intentionally not claimed here.
