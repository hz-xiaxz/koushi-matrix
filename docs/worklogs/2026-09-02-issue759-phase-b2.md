# Issue #759 Phase B2 checkpoint — command receipts and state-only reconciliation

Status: implemented; mandatory different-model review passed in scoped rounds. Hosted CI pending.

## Scope

- Added the state-only `settlement_snapshot` read beside initial `get_snapshot`
  and state+timeline `resync_snapshot`.
- Migrated every normal Tauri command from full snapshot returns to the approved
  v1 `FrontendCommandAdmission`, `FrontendCommandSettlement`, or typed result +
  settlement contract. Initial/resync reads are the only full-snapshot returns.
- Existing exact `RequestOutcomeExpectation`/Core API generations remain the
  terminal authority. Commands without an exact terminal use the Core envelope
  admission path; composer draft commands use the same admission after exact
  lease validation.
- Added exact generations to room-key-reshare and encryption-debug outcomes and
  removed embedded snapshots from submission/composer responses.
- Added one frontend command-watermark reconciler. Delta-before-promise performs
  no read; promise-before-delta performs one state-only snapshot read. Concurrent
  receipts coalesce to the maximum required generation. There is no timer,
  retry/backoff, DOM dependency, or timeline reset/replay for settlement reads.
- Removed normal command-result `setSnapshot` authority and obsolete stale-result
  gates. Presentation epochs remain where they gate dialogs/panels, but Core
  state always enters through the ordered stream or a named snapshot read.
- Browser fake and Tauri/Playwright harness return closed receipts, use monotonic
  generations, and preserve typed composite results. The browser fake emits its
  normal mutations as ordered delta envelopes before resolving receipts; event
  port selection occurs when listeners subscribe so mockIPC ordering is safe.
- Adapter-invalid blank/empty inputs now return fixed validation errors instead
  of fabricating a generation-bearing receipt.
